# 0.4.0 界面与批量更新

当前界面收敛为文件浏览和四个类型标签，选择目录后自动扫描；支持跨页选择和全选筛选结果，选择后直接删除。后台分批完成原有安全计划、同盘暂存和最终删除，就地更新列表和统计，不再因删除自动重扫；失败保留项可在设置中恢复。批量实现见 [bulk-performance.md](bulk-performance.md)。原架构与保护机制继续复用，旧审核 API 不再作为主界面流程。

# 架构与数据流

## 进程边界

React 经 `services/api.ts` 调用强类型 Tauri 2 命令。浏览器模式只展示空界面，不伪造数据。原生目录对话框在 Rust 调用，前端没有通用 fs、shell、SQL 或网络权限。异步命令将扫描、解码、查询和文件操作放入后台；短状态轮询只复制进度。

Backend 持有进程内随机授权 ID 和 `cap_std::fs::Dir`。启动扫描只接受授权 ID，文件操作只接受索引成员或服务器保存的计划 ID。单个活动状态锁避免扫描与文件变更并发；退出时未完成的扫描、计划和操作在重启后标记中断。

## Rust 模块

| 模块 | 职责 |
|---|---|
| model | 扫描、查询、分类、句柄身份和媒体缓存的序列化类型 |
| adapters / discovery | 候选布局、限定范围多账号发现、目录能力和路径边界 |
| classifier | 路径、文件头、扩展名及布局的拒绝优先分类 |
| fs | 文件身份、BLAKE3、QQ 进程检查及 Windows 独占句柄操作 |
| scanner | 有界批次、取消、真实进度、增量分类复用和快照 |
| indexer | SQLite migration、分页、保护覆盖、计划、审计及隔离记录 |
| media | 有限资源图片解码、受限视频 range 读取 |
| cleaner | Dry Run、准入规则、隔离清单、Windows 隔离/恢复/永久删除 |
| policy | 保留期、容量评估、应用衍生缓存淘汰算法 |
| desktop | 将授权、后台任务、媒体服务、策略和清理流程连接 Tauri |

## 扫描和索引

迭代遍历不进入链接/reparse point，256 条一批事务写入 SQLite；约 100ms 推送计数，前端约 350ms 读取状态。只读扫描不修改 QQ 内容。按一级目录、类型、风险、UTC 修改月份统计；大小是逻辑长度，不是实际磁盘分配量。取消保留明确标记的部分结果。

增量扫描仍枚举元数据并打开句柄核对身份；身份、大小、时间、链接数和分类版本相同才复用分类。每次形成独立快照，完整扫描结束才清除消失路径的增量缓存，不使用未经验证的 USN 或 QQ 私有 API。Windows 指纹含卷号、文件 ID、创建/修改/变更时间和链接数；Unix 含 dev/ino/ctime。清理额外逐文件计算完整 BLAKE3，不把增量缓存当作删除证据。

SQLite schema v4：accounts、scan_sessions、indexed_files、classification_results、cleanup_plans、cleanup_operations、protected_items、app_settings、quarantine_items、scan_cache、media_cache、file_removals。启用 WAL、外键和 5 秒 busy timeout。后端生命周期内保留一个无活动事务的连接，避免短连接导致 WAL/SHM 删除抖动；实例文件锁在所有数据库/媒体句柄关闭后释放。migration 支持 v1/v2/v3 升级，拒绝更高版本。查询参数化、固定排序枚举、分页上限 200；UI 文件页 200、隔离页 100、历史最近 100 次扫描/200 次清理。

手动保护按 root/path 叠加到文件、筛选和统计，不能覆盖系统保护。原始扫描快照保留；当前视图按路径和完整指纹扣除本程序已知移除的版本。其他程序造成的外部变化由手动或定时扫描更新。

## 媒体

前端最多并行两个图片任务，只请求视口附近的分页卡片。后端串行解码：编码输入最多 64MiB、尺寸最多 16384、解码分配最多 128MiB；缩略图最大 256，预览最大 2048，失败显示降级信息。内存 LRU 限 32MiB/96 项。

默认没有磁盘媒体缓存。用户明确启用后才在应用目录生成 UUID `.preview` 衍生缩略图，记录身份和摘要。视频使用最多 32 个、15 分钟有效的不透明 token，`qqnt-media` 协议仅主 WebView、GET/HEAD、单范围、每块最多 8MiB，逐次重新核对索引身份；不暴露任意路径 asset protocol。能否解码取决于 WebView2 系统编码器。

## 清理和调度

Dry Run 绑定完成的扫描、授权根、适配器版本、文件身份和摘要，15 分钟失效。标准/高级模式还要求明确审核媒体原件。执行时核对本次选择授权、逐文件保护、布局、QQ 进程、独占访问、指纹/摘要和新分类。旧隔离工作流另检查全局开关。

Windows 操作使用持有的文件句柄重命名或删除，并持有从磁盘根到目标的祖先目录链。隔离在源根下同盘 vault；先持久化 pending 记录和 UUID 恢复清单，再移动。恢复不覆盖已有文件；永久删除只接受已隔离文件。状态和逐文件审计写入应用索引，清单可用于丢失索引后的核对导入。

60 秒调度周期只在应用运行时工作。自动扫描仅覆盖本次进程已授权目录；自动清理只处理应用生成的可重建缩略图。QQ 原件过期或超容量只输出人工审核列表。磁盘剩余容量按所选源盘实际查询。

## 可选插件

LiteLoader manifest v4 插件只读取过滤后的 public-summary.json，并打开固定应用 URI；没有 QQ 数据操作权限。摘要只含计数、大小、时间和布局标志。桌面程序、索引和清理完全独立于 LiteLoader。
