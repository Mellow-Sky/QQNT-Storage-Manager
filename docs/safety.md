# 安全设计

## 默认权限

0.4.0 的扫描始终只读，自动扫描、自动缓存清理和磁盘预览缓存默认关闭。用户在文件列表选择文件后点击“删除”，即明确授权本次选择的永久删除，不再要求审核页或输入确认文字。此操作不修改全局自动清理设置。旧隔离 API 仍保留全局开关和确认文字约束，但主界面不调用旧工作流。恢复区中的“恢复”也只授权本次指定文件。

选择目录才授予本次进程能力，重启后需要重新授权才能预览、定位或变更历史文件。索引和媒体缓存只在应用数据目录，不对 QQ 数据库执行 SQL。拒绝扫描包含应用自身索引的宽泛根。

## 分类拒绝优先

数据库及日志、账号、配置、重要接收文件、收藏、personal_emoji、用户手动保护和只读文件优先为 Protected。SQLite 文件头伪装成图片也保护。未知布局或无法识别的文件保持 Unknown，不允许清理。已识别的图片/视频原件为 ReviewRequired，仅允许用户主动选择并点击删除，不进行自动删除，也不承诺云端恢复。

当前没有经过实际 QQNT 恢复性验证的 SafeCandidate 规则。因此保守模式对 QQ 数据没有可隔离项；自动清理仅针对本程序生成并可重新生成的衍生缩略图。高级年龄/大小/扩展名规则不能放宽保护或未知数据限制。

## 执行前校验

Dry Run 只读核对当前句柄指纹、大小、只读属性、分类和 BLAKE3。计划在应用索引保存，直接删除接口接收扫描会话和具体索引相对路径，后端自动生成并执行精确计划；前端不能传入允许列表或覆盖进程检查。旧隔离接口只接受已存计划 ID。15 分钟失效，执行后不可重放。

全选筛选结果由后端共用列表筛选条件捕获具体索引成员，扣除用户排除项后冻结范围；分页取出最多 64 项逐批执行，取消停止后续操作。扩大选择范围不会放宽逐文件保护。成功移除记录与操作状态在同一索引事务写入，列表和统计直接扣除匹配版本，不需要重新扫描源目录。

实际变更仅在 Windows 本地盘提供，拒绝 UNC。逐项检查 QQ/QQNT/QQGuild/QQProtect 进程，无法枚举时拒绝；提交前再次检查。检查与未来启动 QQ 不能原子化，因此同时用独占文件句柄阻止正在使用文件的移动/删除。不会结束 QQ、解锁文件或提高权限。

拒绝符号链接、所有 reparse point（含 junction）、硬链接、危险相对路径、ADS 和不在索引中的输入。授权保留 cap-std 根句柄；变更时从盘根逐级打开并持有目录句柄，拒绝写入/删除共享，核对 canonical 位置及授权根身份。目标文件 share mode=0，核对卷/文件 ID、链接数、创建/修改/变更时间、长度、内容摘要与新分类。最终调用 SetFileInformationByHandle 对已验证句柄执行重命名或 disposition 删除，不能仅凭字符串路径校验。

同一应用进程内扫描、清理、恢复和设置变更互斥；每项失败写明原因，继续核验后续项。磁盘故障、断电、内核驱动或同权限恶意程序不在绝对保证之内，不应据此省略备份。

## 隔离和恢复

源根内 `.qqnt-storage-manager-quarantine` 是同盘隔离区。owner UUID 与应用索引一致才可写；不会接管冲突目录。每个文件有随机 UUID.bin 和 JSON 清单，记录原相对路径、身份、摘要和状态。先 sync 清单，再移动；应用 SQLite 同时保留 pending 和审计。扫描跳过隔离区，单独展示隔离记录。

同盘隔离尚未释放空间。恢复重新校验身份/摘要/分类，必要时逐级创建原父目录，不覆盖同名文件。永久删除只接受当前隔离中的文件，不能对源目录任意路径执行删除。源/目标出现链接、状态变化或占用时均拒绝。

异常退出后标记中断，pending 项在重新授权后核对。索引丢失可在清理中心导入源盘清单：验证 owner 格式、UUID、原路径、普通文件、身份、长度和摘要后重建记录；恢复仍需独立确认和 QQ 退出检查。清单损坏、缺失、冲突或文件被改动会拒绝导入/操作，不猜测恢复位置。请保留应用索引、隔离文件和清单直到处置完成。

## 隐私和限制

默认离线、无上传、无追踪；CSP 和空前端插件权限限制外部内容。索引包含敏感路径/文件名、身份和审计，没有加密。默认不持久保存图片/视频内容；开启磁盘缩略图会保存衍生媒体，界面明确说明。tracing 不输出文件名和原内容。

扫描并非原子文件系统快照，QQ 并发变化会导致瞬时差异或读取失败。只读访问仍可能被 OS 更新访问时间。逻辑长度不等于可释放空间，硬链接、稀疏、压缩文件和同盘隔离尤其如此。没有任何真实 QQNT 版本的“所有媒体均可恢复”保证。
